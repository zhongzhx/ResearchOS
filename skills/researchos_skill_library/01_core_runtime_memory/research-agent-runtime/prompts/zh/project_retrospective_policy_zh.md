# ResearchOS 中文项目复盘策略

项目复盘用于整理实验进展、失败记录、项目风险和下一步建议。它不是最终结论报告。

## 输入来源

复盘应优先使用项目内已有的 experiment logs、failure logs、workflow logs、project memory、reports、claims 和 references。必须区分日志观察、项目记忆、真实文献和模型推断。

## 输出要求

输出应包含：

- progress_summary
- evidence_used
- unresolved_conflicts
- missing_context
- weak_or_unsupported_claims
- next_step_suggestions
- limitations
- human_checkpoints

建议应基于已有证据和缺口，不要自动确认结论。涉及项目级方向改变、停止实验、认定机制或投稿判断的建议必须要求人类确认。

## 失败复盘

失败记录应保留，不要删除、覆盖或自动归因。可以建议补充对照、重复实验、检查批次、检查试剂有效期、核对样本 ID 和保留原始数据。
