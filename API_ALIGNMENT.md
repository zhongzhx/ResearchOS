## Main Findings

- Default chat remains on `POST /research-os/agent/chat` through `sendLegacyChat`; it does not call product feature flows, task lifecycle routes, demo flow, or the dual-agent coordinator.
- `sendLegacyChat(message, projectId, conversationId, sessionId)` sends `message`, `project_id`, `conversation_id`, and `session_id`; missing project ids are normalized to the visible stable default `default`.
- `runCoordinator(userQuery, projectId, conversationId, sessionId)` sends `user_query`, `project_id`, `conversation_id`, and `session_id`, and active UI only calls it when dual-agent experimental mode is enabled.
- `POST /api/agents/coordinator/run` remains available only behind explicit dual-agent experimental mode in `web_client/views/chat.js`.
- Product feature list/detail endpoints are implemented, but feature execution from the active UI is treated as `not_connected` unless the UI is using a `demo_only` GET endpoint.
- The chat demo button now uses GET `/api/demo/product-flow`.
- Contract spelling for tests and reports: GET /api/demo/product-flow.
- The literature workflow button now uses `GET /api/product/features/literature_harvest_workflow/demo`; campus-network and browser-authorization controls are disabled as `not_connected`.
- MemoryOS endpoints are wired but experimental and gated by `RESEARCHOS_MEMORYOS_ENABLED`.
- Skill catalog, pipeline, resolver, pending skill, and route APIs are wired but experimental and gated by `RESEARCHOS_DUAL_AGENT_API_ENABLED`.
